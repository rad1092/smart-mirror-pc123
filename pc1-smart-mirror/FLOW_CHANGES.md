# 흐름 변경 메모

이 문서는 발표 준비 이후 저장소와 사용자 흐름이 어떻게 정리되었는지 짧게 남기는 메모입니다.
세부 파일 단위 변경은 [CHANGELOG.md](CHANGELOG.md) 를 기준으로 보고, 여기서는 "왜 이렇게 정리했는가" 만 남깁니다.

---

## 2026-05-22 기준 정리 방향

- 발표용 임시 자산과 설명 문서는 최대한 덜어내고, 포트폴리오에 필요한 정보만 남긴다.
- README 는 비전공자도 따라할 수 있는 설치·빌드 안내를 우선한다.
- CHANGELOG 는 작은 작업까지 남겨서 개발 흐름을 한 번에 읽을 수 있게 유지한다.
- 화면 문구는 내부 시스템 이름보다 사용자가 이해하는 표현을 우선한다.

## 최근 흐름 변경

### 1. 발표용 저장소에서 포트폴리오용 저장소로 전환
- `PPT_FLOW_SUMMARY_KO.md`, `test-api.http`, `scripts/api_probe.mjs` 같은 발표/개발 보조 파일을 정리했다.
- `.env` 추적을 해제하고 `.env.example` 만 남겨 외부 공유에 안전한 형태로 맞췄다.
- README 를 쇼케이스 + 설치 가이드 구조로 다시 썼다.

### 2. CHANGELOG 를 장기 기록 문서로 재작성
- 커밋이 3일에 몰려 보여도 실제 작업 흐름은 4주에 걸쳐 있었다.
- 그래서 개발 히스토리를 주차 단위로 재배치해 프로젝트 진행 맥락이 보이도록 정리했다.
- 이번 정리부터는 포트폴리오 문서 초안과 사용자 문구 변경도 함께 기록한다.

### 3. 사용자 화면 문구 정리
- `PC3` 같은 내부 시스템 이름은 사용자 화면에서 의미가 약해 가능한 한 감췄다.
- 대신 `오늘 루틴`, `운동 기록`, `분석 근거`, `프로필 생성` 같은 표현으로 바꿨다.
- 목적은 데모/설치 환경에서 비전공자도 화면만 보고 이해하게 만드는 것이다.

### 4. 포트폴리오 문서 분리
- `portfolio/README.md` 는 외부에 보여줄 자기소개/대표 프로젝트 소개 초안이다.
- `portfolio/case-studies/smart-mirror.md` 는 프로젝트를 깊게 설명하는 케이스 스터디 초안이다.
- `portfolio/resume-notes.md` 는 이력서, 자기소개서, 면접 답변에 재사용할 문장 메모다.
